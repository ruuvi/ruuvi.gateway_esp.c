## Objective

Create a Python functional test for **ETSI EN 303 645 / ETSI TS 103 701 test case 5.3-13-2, Test
Unit b: Unrestricted public access to the published software-update support period**.

The test must fetch the manufacturer's published lifecycle/support-period page over the public
Internet and objectively verify that the declared URL is reachable **without registration, paywall,
or authentication**. This is a public-document accessibility check, not a device test.

Scope boundary: Unit b verifies only that the lifecycle resource is _publicly accessible without
restriction_. The adjacent Units **a** (the page actually lists the gateway "as described") and
**c** (a binding support timeframe is published) are documentation-content judgements that the
source records as **FAIL** and that are classified **HYBRID/MANUAL**. They are **out of scope**
here. Do not scrape the page for the product name, for a "5 years" timeframe, or for the `? years`
placeholder.

Important interpretation: the source self-assessment fails the overall case because of the content
gaps in Units a and c, but **Unit b is a source PASS** because the URL itself is publicly reachable.
This task automates only Unit b and must not inherit the overall-case FAIL.

## Procedure

### 1. Open the evidence log

Create the log before any network activity and record the test identity, fixed target URL, and the
accessibility policy constants.

### 2. Fetch the lifecycle page

Call `fetch_public_resource` for `TARGET_URL` with the constants above and capture full evidence.

### 3. Evaluate accessibility (objective boundaries)

The resource is **publicly accessible without restriction (PASS)** only if **all** of the following
hold:

- the final status is in `ALLOWED_FINAL_STATUS` (`200`);
- the final scheme is `https` and no redirect hop downgraded to `http`;
- the final host is in `ALLOWED_HOSTS`;
- no `WWW-Authenticate` header appeared anywhere and the final status is neither `401` nor `403`;
- the redirect chain did not land on a login/SSO/registration/paywall host outside `ALLOWED_HOSTS`;
- the final `Content-Type` begins with `text/html`;
- the body length is at least `MIN_BODY_BYTES` (non-empty).

Classify outcomes:

- **FAIL (compliance)** — reachable at the network/TLS layer but objectively restricted:
  `401`/`403`, any `WWW-Authenticate` challenge, a redirect to a login/registration/paywall host,
  `404`/`410`, an `https -> http` downgrade, a non-`text/html` final content-type, or an empty body.
- **ERROR (infrastructure/setup)** — DNS failure, TLS verification failure, connection refused,
  connect/read timeout, redirect loop/overflow, or a `5xx`/`429` transient response. Never convert
  these into PASS or FAIL.

Do not fail this test because the page omits the gateway model or a binding support timeframe —
those belong to Units a and c and are explicitly out of scope.

An outside-host or non-HTTPS redirect is recorded without being followed. Malformed redirects are
ERROR. Preserve an earlier observed assertion FAIL in per-check evidence if a later transport,
protocol, or transient-response error makes the overall verdict ERROR.

### 4. Produce the verdict

Emit a single result for `SupportPeriodPublication-UnrestrictedPublicAccess` and the overall
verdict.

| Exit code | Meaning                                                             |
| :-------- | :------------------------------------------------------------------ |
| `0`       | PASS — the lifecycle URL is publicly accessible without restriction |
| `1`       | FAIL — the lifecycle URL is objectively restricted/inaccessible     |
| `2`       | ERROR — infrastructure/setup failure; no authoritative observation  |
