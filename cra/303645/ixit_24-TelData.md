# IXIT 24-TelData: Telemetry Data

The following declarations list the telemetry schemas, system diagnostics metrics, and environmental
sensor collection layers generated by the Device Under Test (DUT) and transmitted to receiving
target infrastructures.

---

## Table C.24: IXIT 24-TelData (Telemetry Data)

### **ID**: TelData-System-Status-Heartbeat

#### Description

A structured diagnostics status JSON payload compiled periodically by the gateway application layer
and transferred outbound to the configured diagnostics telemetry endpoint.

* **Payload Inventory:** Tracks operational uptime indicators (`UPTIME`), active connection
  mediums (`CONNECTION`), software versions (`ESP_FW`, `NRF_FW`), internal memory stack block
  statistics (`TOTAL_FREE_BYTES_INTERNAL`, `LARGEST_FREE_BLOCK_INTERNAL`, `MIN_FREE_STACK_SIZE` per
  running FreeRTOS task), interface connection stability trackers (`NUM_CONN_LOST`,
  `NRF_LOST_ACK_CNT`), and a dynamic execution transaction tracking token (`NONCE`).
* **Sensor Tracking:** Reports the counts and public hardware MAC addresses of environmental beacons
  actively or historically parsed by the radio layer (`ACTIVE_SENSORS`, `INACTIVE_SENSORS`).

#### Purpose

The metrics are collected and evaluated to calculate device reliability baselines, debug runtime
memory allocations, optimize task stack boundaries, and support continuous firmware maintenance.

#### Security Examination

The telemetry data is examined outside the DUT by the associated service infrastructure of Ruuvi
Innovations Oy (or by the operator's private collection endpoint if custom routing is defined).
Automated server-side tracing routines process the incoming arrays to identify stack utilization
anomalies or resource depletion behaviors, enabling the developers to determine potential security
flaws or active denial-of-service (DoS) vectors.

#### Personal Data

`PersData-Network-IP-Footprints`, `PersData-Gateway-MAC-Identifier`

### **ID**: TelData-Crash-Panic-Diagnostics

#### Description

System fault debug telemetry captured locally upon a critical operating thread exception or system
crash state.

* **Local Logging:** In the event of an unhandled core exception, the runtime kernel intercepts the
  fault loop, outputting a descriptive register dump string (containing `Guru Meditation Error`
  descriptors, CPU registers, execution backtrace arrays, and active image ELF hashes) directly to
  the local diagnostic `LogIntf-USB-UART-Log-Stream`.
* **Telemetry Reporting:** Upon recovering from the subsequent hardware restart, the application
  reads the archived crash string out of persistent memory buffers and appends it directly to the
  next outbound status packet inside the parameters matching `"RESET_REASON": "PANIC"` and
  `"RESET_INFO"`.

#### Purpose

Enables systems deployment teams and software engineering staff to diagnose coding oversights, task
deadlocks, or illegal hardware access states to maintain long-term platform stability.

#### Security Examination

The telemetry data is processed outside the DUT by the engineering staff of Ruuvi Innovations Oy (or
the private destination administrator) using cross-referencing debugging tools like GDB against
unstripped production ELF symbol files. This manual and automated analysis determines whether the
crash was caused by an isolated runtime edge case or a malicious memory boundary transgression
attempt (such as buffer overflow injections or instructions modification exploits).

#### Personal Data

`PersData-Network-IP-Footprints`, `PersData-Gateway-MAC-Identifier`

---

### **ID**: TelData-Environmental-Sensor-Payloads

#### Description

A stateless consolidated structural message array (`data`) containing raw, processed radio
parameters and environmental advertisement data captured from local Bluetooth Low Energy beacons.

* **Payload Inventory:** Combines the gateway identifier string (`gw_mac`), an epoch tracking
  identifier (`timestamp`), a transaction token (`nonce`), and an open dictionary containing the
  hardware addresses of reporting external beacons.
* **Beacon Attributes:** Each individual entry maps the radio link parameters (`rssi`, `ble_phy`,
  `ble_chan`, `ble_tx_power`), a secondary event timestamp, and the raw data block received over the
  air (`data`) containing raw environmental values (temperature, humidity, air pressure, air
  quality, or motion vectors).

#### Purpose

Provides the core data-forwarding functionality of the gateway, routing localized raw metrics
streams out to central storage arrays, automation hubs, or cloud analytics backends.

#### Security Examination

N/A. The raw radio payload records are treated as stateless telemetry input streams and are not
evaluated for internal gateway device security anomalies by either the device or the associated
service.

#### Personal Data

`PersData-Network-IP-Footprints`, `PersData-Gateway-MAC-Identifier`
